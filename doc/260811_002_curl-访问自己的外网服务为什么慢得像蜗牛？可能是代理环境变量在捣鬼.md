# curl 访问自己的外网服务为什么慢得像蜗牛？可能是代理环境变量在捣鬼

> **日期**: 2026-08-11  
> **分类**: 踩坑记录  
> **标签**: curl, 代理, 网络排查, Linux  
> **来源**: hermes

---

## 背景/问题

在 NAS 上用 curl 测试自己的外网服务（通过 Cloudflare Tunnel 暴露的域名），明明本地服务响应只要 1 毫秒，但从外网域名走却要 10 秒还超时。明明网络没问题，其他子域名也都正常，就是主站慢得离谱。

## 原因分析

问题出在 **shell 的代理环境变量**上。

NAS 上之前装过代理软件，设置了环境变量：

```bash
https_proxy=http://192.168.0.104:7890
http_proxy=http://192.168.0.104:7890
```

这意味着 **所有 curl 请求都会先走到代理服务器**，包括访问自己外网域名的请求！流程变成了：

```
curl https://你的域名
  -> 先连到代理服务器 (192.168.0.104:7890)
  -> 代理再连到 Cloudflare
  -> Cloudflare 再通过 Tunnel 回到本地服务端口
```

绕了一大圈！而且如果代理服务器当时挂了或者认证失败（返回 407），请求就会卡住直到超时。

更坑的是，用 `curl -vvv` 时会看到 `Proxy-Authorization: ***REDACTED*** ***` 这样的输出，说明请求确实走了代理，但很多人会忽略这个细节。

## 解决方案

### 第 1 步：确认是否走了代理

```bash
# 查看当前代理环境变量
echo $https_proxy
echo $http_proxy
echo $no_proxy

# 用 -vvv 看详细连接过程
curl -vvv https://你的域名 2>&1 | head -20
# 如果看到 "Uses proxy env variable https_proxy" 就是中招了
```

### 第 2 步：临时绕过代理测试

```bash
# 方法1：用 --noproxy 参数
curl -sS -o /dev/null -w "HTTP %{http_code}, time %{time_total}s\n" --noproxy '*' https://你的域名

# 方法2：临时清空环境变量
https_proxy= curl -sS -o /dev/null -w "HTTP %{http_code}\n" https://你的域名
```

如果绕过代理后秒回，那就确认是代理环境变量的问题。

### 第 3 步：永久修复

**方案 A：把本地域名加入 no_proxy（推荐）**

```bash
# 在 ~/.bashrc 或 ~/.profile 里设置
export no_proxy="localhost,127.0.0.1,192.168.0.0/24,*.你的域名"
```

这样访问自己的域名就不走代理了，访问外网（GitHub 等）还能继续走代理。

**方案 B：如果代理已经不用了，直接清掉**

```bash
# 从 ~/.bashrc 里删掉 https_proxy/http_proxy 的 export 行
unset https_proxy http_proxy
```

### 第 4 步：用分阶段计时定位瓶颈

排查网络慢的时候，用 curl 的 `-w` 参数看每个阶段花了多少时间：

```bash
curl -sS -o /dev/null -w \
  "DNS: %{time_namelookup}s\n\
   Connect: %{time_connect}s\n\
   TLS: %{time_appconnect}s\n\
   FirstByte: %{time_starttransfer}s\n\
   Total: %{time_total}s\n\
   Size: %{size_download}\n" \
  --noproxy '*' https://你的域名
```

输出示例：
```
DNS: 0.05s       # 域名解析快
Connect: 0.28s   # TCP 连接正常
TLS: 0.90s       # TLS 握手偏慢
FirstByte: 1.52s # 首字节时间
Total: 6.20s     # 总时间明显偏长
Size: 54283      # 54KB 花了 6 秒
```

哪个阶段时间长，问题就在哪。DNS 慢→换 DNS 服务器；Connect 慢→网络不通；TLS 慢→可能是代理或 CDN 问题。

## 避坑提示

- **curl 默认会读环境变量**：`https_proxy`/`http_proxy` 是 curl 的「隐形配置」，很多人不知道它的存在，排查网络问题时第一件事应该检查这个
- **`no_proxy` 是救命稻草**：把本地 IP 段和自己的域名加进去，既不影响访问外网走代理，又不会让本地请求绕弯路
- **别在 NAS 上装代理软件**：NAS 是服务端，不需要翻墙工具。如果真需要代理某些请求，用 `no_proxy` 严格限定范围
- **`curl -vvv` 输出要看全**：第二行就告诉你走没走代理，但很容易被忽略
