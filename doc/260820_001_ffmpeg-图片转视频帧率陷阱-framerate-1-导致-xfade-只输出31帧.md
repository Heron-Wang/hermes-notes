# ffmpeg 图片转视频帧率陷阱：-framerate 1 导致 xfade 只输出 31 帧

## 问题/背景

在 news-video 视频管线中，使用 ffmpeg 将新闻 PPT 截图（PNG 图片）+ TTS 音频合成视频片段时，最终通过 xfade 转场合成的视频**只有 31 帧 / 1 秒**，而音频时长正常（114.9 秒）。视频画面只停留在片头第一帧，字幕也只显示第一句。

## 关键操作

### 根因分析

`make_clip` 函数用 `-framerate 1` 替代 `-loop 1`（之前 `-loop 1` 导致 ffmpeg 卡住），意图是每秒读 1 帧图片避免无限循环。但副作用是：

```
-framerate 1   →  每秒只读 1 帧图片
-t 19.9        →  限制输入时长为 19.9 秒
-r 30          →  输出 30fps
```

**关键误解**：`-t` 限制的是**输入时长**而非输出时长。`-framerate 1` 意味着 19.9 秒只读了约 20 帧图片，但 `-r 30` 输出 30fps，所以最终只输出了不到 1 秒的 30fps 视频（约 30 帧）。

### 修复方案

改回 `-loop 1`（循环图片），但用 `-t` 限制**输出时长**（而非输入时长），并去掉 `-shortest`：

```python
def make_clip(image_path, audio_path, output_path):
    dur = get_audio_duration(audio_path)
    cmd = [
        "ffmpeg", "-y",
        "-loop", "1",                    # 循环读取图片
        "-i", image_path,                # 输入图片
        "-i", audio_path,                # 输入音频
        "-t", str(dur),                  # 限制输出时长（不是输入！）
        "-r", "24",                      # 输出帧率
        "-c:v", "libx264",
        "-pix_fmt", "yuv420p",
        "-c:a", "aac",
        "-shortest", "",                 # 不要用 -shortest！
        output_path,
    ]
    # 过滤空参数
    cmd = [c for c in cmd if c]
```

### 验证结果

```
修复前: 30 帧 / 1 秒 / 1fps
修复后: 624 帧 / 26 秒 / 24fps ✅
```

最终完整视频：1920×1080 | 114.9s | 2642 帧 | 35 条字幕 | BGM 混音 | 3.6MB

## 经验/坑

### ffmpeg 图片转视频的三个陷阱

| 陷阱 | 原因 | 修复 |
|------|------|------|
| `-loop 1` 导致 ffmpeg 卡住 | 无限循环读取图片帧，没有退出条件 | 配合 `-t` 限制输出时长 |
| `-framerate 1` 导致视频只有 1 秒 | `-t` 限制输入时长，1fps × 19.9s 只读 20 帧 | 用 `-loop 1` + `-t` 限制输出时长 |
| `-shortest` 截断视频 | 以最短输入为准，BGM 短片段导致视频被截到 1 秒 | 去掉 `-shortest` |

### 核心知识点

- **`-framerate`** 控制的是**输入图片的读取速率**，不是输出帧率
- **`-r`** 控制的是**输出帧率**
- **`-t`** 在 `-i` 之前限制输入时长，在 `-i` 之后限制输出时长
- **`-loop 1`** 循环读取输入，配合 `-t`（输出侧）可以正确控制视频时长
- **`-shortest`** 以最短流为准截断输出，混音 BGM 时容易误截断视频
