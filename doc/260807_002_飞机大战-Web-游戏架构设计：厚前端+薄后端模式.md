## 背景

用 Python + Canvas 实现了一个复古像素风飞机大战游戏。核心设计思路是「厚前端 + 薄后端」——所有游戏逻辑跑在浏览器里，服务器只负责交付 HTML 文件。

## 为什么用纯前端游戏架构？

| 方案 | 服务器负担 | 实时性 | 实现复杂度 |
|------|----------|--------|-----------|
| 纯前端 | 极低（只返回 HTML） | 零延迟 | 低 |
| 前端 + WebSocket | 高（需维护连接） | 实时 | 高 |
| 前端 + HTTP 轮询 | 中 | 有延迟 | 中 |

飞机大战是**单人游戏**，所有逻辑（移动、碰撞、AI、计分）都在本地完成，不需要服务器参与游戏逻辑。

## 整体架构

```
浏览器（全部游戏逻辑）
├── HTML/CSS    → UI 布局、HUD、遮罩层
├── Canvas 2D   → 渲染引擎（星空/飞机/子弹/敌机/道具/粒子）
├── JS 游戏引擎 → 状态管理 + 物理碰撞 + AI + 输入
└── Web Audio   → 8-bit 音效

         ↑ HTTP

Python http.server (:8086)
├── GET /         → 返回 HTML（21KB 单文件）
├── GET /health   → JSON 健康检查
└── 404           → 兜底

         ↑ Cloudflare Tunnel

外网用户 → plane.heronwang.cn
```

## 分层设计

| 层 | 职责 | 实现方式 |
|----|------|---------|
| 网络层 | HTTP 服务、路由 | Python http.server，3 条路由 |
| 传输层 | 外网穿透 | Cloudflare Tunnel（QUIC 隧道） |
| 表现层 | 画面渲染 | Canvas 2D API + shadowBlur 发光 |
| 逻辑层 | 游戏循环、碰撞、AI | 纯 JS requestAnimationFrame |
| 输入层 | 触摸/键盘/鼠标 | touchstart/move/end + keydown |
| 音效层 | 道具拾取音 | Web Audio API OscillatorNode |

## 游戏循环

```
requestAnimationFrame(loop)
    │
    ├── 1. 计算 dt（帧间隔，限制 ≤50ms 防跳帧）
    │
    ├── 2. update(dt) ── 逻辑更新
    │   ├── 星空滚动（50-80 颗星，循环重生）
    │   ├── 玩家自动射击（按 fireRate 定时）
    │   ├── 子弹移动 + 碰撞检测
    │   │   ├── 玩家子弹 → 击中敌机 → 减血/消灭/掉落道具
    │   │   └── 敌机子弹 → 击中玩家 → 减血/无敌帧
    │   ├── 敌机生成（难度随分数递增，刷新间隔缩短）
    │   ├── 敌机移动 + 撞机检测 + 敌机射击
    │   ├── 道具移动 + 拾取检测
    │   ├── 粒子更新（爆炸碎片衰减）
    │   └── HUD 更新（血条/分数/炸弹数/护盾）
    │
    ├── 3. draw() ── 画面渲染
    │   ├── 黑色背景 + 星空
    │   ├── 闪光层（炸弹效果衰减）
    │   ├── 道具（发光圆 + 图标）
    │   ├── 子弹（玩家绿色/敌方红色）
    │   ├── 敌机（三种形状 + 血条）
    │   ├── 粒子（爆炸碎片）
    │   └── 玩家飞机（机身/驾驶舱/火焰/护盾）
    │
    └── 4. 递归调用下一帧
```

## 碰撞检测

全部用**圆形碰撞**（距离平方比较），避免三角函数：

```javascript
// 两圆碰撞：圆心距离 < 半径之和
const dx = a.x - b.x;
const dy = a.y - b.y;
if (dx*dx + dy*dy < (a.r + b.r) ** 2) {
  // 碰撞！
}
```

> **为什么用距离平方而不是距离？** 避免 `Math.sqrt()` 开方运算，性能更好。比较 `dist² < r²` 和 `dist < r` 结果一样。

| 碰撞类型 | 检测方式 | 结果 |
|---------|---------|------|
| 玩家子弹 vs 敌机 | 圆形碰撞 | 敌机减血/消灭，8% 概率掉道具 |
| 敌机子弹 vs 玩家 | 圆形碰撞 | 玩家减血，触发 0.5s 无敌 |
| 敌机 vs 玩家 | 圆形碰撞 | 玩家减血 20，敌机消失 |
| 道具 vs 玩家 | 圆形碰撞 | 拾取道具 |

## 输入控制架构

```
触摸控制（手机）
├── touchstart → 记录触摸点 + 双击检测（<300ms 释放炸弹）
├── touchmove  → 更新目标坐标
├── touchend   → 释放触摸
└── updatePlayerPos() → 每帧平滑插值移动玩家到触摸点

鼠标控制（桌面）
├── mousedown → 开始拖动
├── mousemove → 更新目标坐标
├── mouseup   → 停止
└── dblclick  → 释放炸弹

键盘控制（桌面）
├── WASD/方向键 → 直接位移
├── 空格        → 释放炸弹
└── keyboardMove() → 每帧独立循环
```

> **关键设计：** 触摸和鼠标控制用的是「目标坐标 + 平滑插值」模式（飞机追逐手指位置），而非直接跟随。这样手感更丝滑，不会跳变。

## 难度曲线

```
敌机刷新间隔 = max(0.4s, 1.5s - score/5000)

分数    刷新间隔    难度
  0      1.5s       简单
5000      0.5s      中等
10000     0.4s      困难（封顶）
```

> **设计思路：** 难度随时间递增但有上限，避免后期太难导致挫败感。封顶在 0.4 秒保证玩家有反应时间。

## 道具系统设计

```
定时掉落（每 8 秒）+ 击杀掉落（8% 概率）

道具类型    权重    效果
───────────────────────────
hp        30%    恢复 30 HP
bullet    30%    子弹升级（1→2→3路，射速+，伤害+）
shield    20%    5 秒护盾（免疫一切伤害）
bomb      20%    获得炸弹（双击清屏）
```

子弹升级三阶段：
- Level 1：单发直射
- Level 2：双发并行
- Level 3：三发扇形散射

## 渲染优化技巧

| 技巧 | 说明 |
|------|------|
| shadowBlur 发光 | 道具、子弹、敌机有霓虹发光效果，用完立即 shadowBlur=0 |
| 粒子复用 | 爆炸粒子 12 个/次，life 衰减后自动移除 |
| 星星上限 | 最多 80 颗，超出移除最旧的 |
| dt 限制 | Math.min(0.05, dt) 防止切后台回来后大跳帧 |
| image-rendering:pixelated | 像素风格渲染 |
| Canvas 全屏 | 自适应 window.innerWidth/innerHeight |

## 音效系统

```javascript
// Web Audio API 生成 8-bit 方波音效
function beep(type) {
  const o = audioCtx.createOscillator();  // 振荡器
  const g = audioCtx.createGain();        // 增益（音量包络）
  o.type = 'square';                     // 方波 = 复古音色
  o.frequency.value = {hp:660, bullet:880, shield:440, bomb:220}[type];
  // 指数衰减包络
  g.gain.exponentialRampToValueAtTime(0.001, ...);
}
```

不同道具用不同频率：血包 660Hz、子弹 880Hz、护盾 440Hz、炸弹 220Hz，低音越沉效果越强。

## 部署架构

```
plane.heronwang.cn
        ↓ HTTPS
Cloudflare 边缘节点（缓存 HIT）
        ↓ QUIC Tunnel
本地 :8086
        ↓
Python http.server（systemd 管理）
├── Restart=always（崩溃自动重启）
├── 开机自启
└── 单文件 21KB HTML 返回
```

## 总结

这个飞机大战的架构核心是**「厚前端 + 薄后端」**：

- **前端**承担了全部游戏逻辑：Canvas 渲染引擎、实体系统、碰撞检测、AI、难度曲线、音效、输入控制
- **后端**只做一件事：返回 HTML 文件（21KB）
- **Cloudflare** 负责外网穿透 + 缓存 + HTTPS

这种架构非常适合轻量级 Web 游戏，服务器成本极低，玩家体验流畅，离线也能玩。
