# 5 种编程语言性能测评：C/C++/Rust/Go/Python 怎么对比才公平

---

## 背景：想客观对比 5 种语言的性能

不同语言性能差距到底多大？怎么保证对比有说服力？

## 怎么保证公平？

| 措施 | 为什么 |
|------|--------|
| 相同算法 | 所有语言手写相同排序，不调标准库 |
| 相同数据 | 固定随机种子 seed=42 |
| 相同优化级别 | C/C++ 用 -O2，Rust 用 -O |
| 防编译器优化 | 用 volatile 防止循环被优化掉 |
| 多次运行取均值 | 每项跑 5 次取平均 |

## 测什么？

### 1. 数组运算（CPU 密集型）
两个 N 元素 double 数组做加减乘除。

### 2. 排序算法
冒泡 O(n²) vs 快排 O(n logn) vs 归并 O(n logn)。

数据规模：1K / 10K / 100K。

## 结果亮点

| 测试 | 最快 | C | C++ | Rust | Go | Python |
|------|------|---|-----|------|----|--------|
| 数组加法 100K | C++ 0.15ms | 0.43 | 0.15 | 0.31 | 0.20 | 7.0 |
| 快排 100K | Rust 11.4ms | 13.1 | 11.7 | 11.4 | 12.1 | 184 |
| 归并 100K | C 16.1ms | 16.1 | 16.2 | 19.6 | 25.9 | 285 |
| 冒泡 10K | Rust 112ms | 304 | 286 | 112 | 298 | 4786 |

**关键发现：**
- 编译型语言差距不大，通常 2-3 倍以内
- Python 比编译型慢 15-50 倍
- Rust 排序最快，C/C++ 数组运算最快

## 内存占用怎么测？

用读取 /proc/self/statm 测量实际 RSS（物理内存）：

```python
def get_rss_kb():
    with open('/proc/self/statm') as f:
        return int(f.read().split()[1]) * 4  # 4KB per page
```

> **为什么不用公式估算？** 一开始用公式算，结果所有语言一样。实际测量发现 Python list 比 C 数组占 5 倍内存（每个元素是 PyObject 指针）。

## 避坑提示

1. **别用 time.time()**：精度不够，Python 用 perf_counter()，C 用 clock_gettime
2. **别调标准库排序跟手写排序比**：标准库是高度优化的，不公平
3. **编译器优化一定要开**：不开 -O2 的话 C 也快不了多少
4. **内存测量要测增量**：测分配前后的 RSS 差值
