# WebGL 全屏四边形为什么只渲染了中心一小块？顶点着色器 NDC 修复

> **日期**: 2026-08-18  
> **分类**: 踩坑记录  
> **标签**: WebGL, Three.js, GLSL, Shader, 光线追踪  
> **来源**: hermes

---

## 背景/问题

做了一个 Schwarzschild 黑洞光线追踪可视化项目（GARGANTUA），技术栈是 Three.js + WebGL + GLSL fragment shader。架构很直接：一个 PlaneGeometry(2,2) 全屏四边形 + 自定义 ShaderMaterial，fragment shader 里对每个像素发射光线、积分零测地线、渲染黑洞和吸积盘。

页面加载正常，没有 shader 编译错误，没有 WebGL 初始化失败，FPS 计数器在跑（5 FPS），控制台零报错。但画面**全黑**——不是"WebGL 不支持"的错误覆盖层，而是 canvas 确实在渲染，只是每个像素都是 [0,0,0,255]。

GPU 日志里有一条可疑警告：

```
HLSLCompiler.cpp:254 warning X4000: 
use of potentially uninitialized variable (f_chromaticAberration)
```

但这个警告不会导致黑屏。真正的问题在别处。

## 原因分析

### 核心问题：顶点着色器错误地应用了透视相机矩阵

原始的 `fullscreen.vert`：

```glsl
varying vec2 vUv;

void main() {
    vUv = uv;
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}
```

Three.js 的 ShaderMaterial 会自动注入 `projectionMatrix` 和 `modelViewMatrix`。这段代码看起来很标准——但问题是：**渲染场景用的是 PerspectiveCamera（z=18 看原点），PlaneGeometry(2,2) 放在原点**。

计算一下：
- 相机在 z=18，看向原点
- 四边形顶点在 (-1,-1,0) 到 (1,1,0)
- 在相机空间，这些顶点在 z=-18 处
- PerspectiveCamera FOV=60°，在 z=-18 处可见高度 = 2 × 18 × tan(30°) ≈ 20.78
- 四边形高度 2，占可见高度的 2/20.78 ≈ **9.6%**

所以全屏四边形只覆盖了屏幕中心约 10% 的区域！其余 90% 是 clearColor（黑色）。

### 为什么中心区域也是黑的

那 10% 的像素确实在执行 fragment shader，但这些像素的 NDC 坐标都接近 (0,0)——对应的光线方向几乎直指黑洞中心。光线追踪几十步后全部命中事件视界，fragment shader 返回 `vec3(0.0)`（纯黑）。

所以整个画面都是黑的，只是原因不同：
- 中心 10%：shader 执行了，但光线被黑洞吞噬
- 外围 90%：根本没执行 shader，显示 clearColor

## 排查过程

### 第一步：确认不是 WebGL 初始化失败

通过 `browser_console` 在页面执行 JS：

```javascript
const c = document.querySelector('#canvas-container canvas');
const gl = c.getContext('webgl2');
// 检查 shader 编译状态
const prog = gl.getParameter(gl.CURRENT_PROGRAM);
const shaders = gl.getAttachedShaders(prog);
shaders.forEach(s => {
    console.log(gl.getShaderParameter(s, gl.COMPILE_STATUS)); // true
    console.log(gl.getShaderInfoLog(s)); // (empty)
});
console.log(gl.getProgramParameter(prog, gl.LINK_STATUS)); // true
```

编译和链接全部成功，没有错误。

### 第二步：读取画布像素值

```javascript
const px = new Uint8Array(4);
gl.readPixels(640, 288, 1, 1, gl.RGBA, gl.UNSIGNED_BYTE, px);
// [0, 0, 0, 255] — 纯黑，alpha=255

// 采样 20×20 网格
for (let y = 0; y < 20; y++) {
    for (let x = 0; x < 20; x++) {
        gl.readPixels(...);
        // 全部 [0, 0, 0, 255]，无一例外
    }
}
```

整个画布没有任何一个非黑像素。

### 第三步：检查 shader 源码确认是新版还是缓存

```javascript
const vertSrc = gl.getShaderSource(vertShader);
vertSrc.includes('projectionMatrix'); // true — 仍在用旧版！
```

浏览器缓存了 .vert 文件。Python `http.server` 不发 Cache-Control 头，浏览器自行缓存。

## 解决方案

### 修复 1：顶点着色器直接输出 NDC 坐标

```glsl
// fullscreen.vert — 修复后
varying vec2 vUv;

void main() {
    vUv = uv;
    gl_Position = vec4(position.xy, 0.0, 1.0);
}
```

PlaneGeometry(2,2) 的顶点坐标已经是 (-1,-1) 到 (1,1)，正好是 NDC 范围。直接输出 `vec4(position.xy, 0.0, 1.0)` 让四边形覆盖整个屏幕，绕过相机矩阵。

相机位置和旋转通过 uniform（`uCameraPos`、`uCameraRot`）传递给 fragment shader，在 `main()` 里用 `gl_FragCoord` 计算每个像素的光线方向：

```glsl
// raytracer.frag main()
void main() {
    vec2 uv = gl_FragCoord.xy / uResolution.xy;
    vec2 ndc = (uv - 0.5) * 2.0;
    ndc.x *= uResolution.x / uResolution.y;
    
    float focal = 1.0 / tan(radians(uFov) * 0.5);
    vec3 rayDir = normalize(uCameraRot * vec3(ndc.x, ndc.y, -focal));
    
    RayHit hit = traceRay(uCameraPos, rayDir);
    // ...
}
```

### 修复 2：shader fetch 加 cache-busting

```javascript
async function loadShaders() {
    const v = '?v=' + Date.now(); // cache-busting
    const [rayFrag, compFrag, fullVert] = await Promise.all([
        fetch(CONFIG.shaderPaths.raytracer + v).then(r => r.text()),
        fetch(CONFIG.shaderPaths.composite + v).then(r => r.text()),
        fetch(CONFIG.shaderPaths.fullscreen + v).then(r => r.text()),
    ]);
    return { rayFrag, compFrag, fullVert };
}
```

## 方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **直接 NDC 输出** | `gl_Position = vec4(position.xy, 0.0, 1.0)` | 最简单，零矩阵运算 | 需手动传相机 uniform |
| **OrthographicCamera** | 用正交相机替代透视相机 | Three.js 原生支持 | 多一个相机对象，OrbitControls 需适配 |
| **RawShaderMaterial** | 不自动注入矩阵，完全手写 | 完全控制 | 需手动声明所有 attribute/uniform |

推荐方案 1（直接 NDC），因为全屏四边形本来就是 2D 的，不需要任何相机投影。

## 避坑提示

- **Three.js ShaderMaterial 自动注入 projectionMatrix/modelViewMatrix**：如果你不写 `projectionMatrix * modelViewMatrix`，它们不会被使用。但如果你写了，就会用当前相机的投影——对于全屏四边形场景，这是错误的
- **Python http.server 不发 Cache-Control 头**：浏览器会缓存 .js/.frag/.vert 文件。修改 shader 后必须加 cache-busting 参数或手动清除缓存
- **readPixels 的坐标系**：原点在左下角，Y 轴向上。和 DOM 的左上角原点不同
- **SwiftShader 软件渲染会卡死**：headless Chromium 没有 GPU，用 SwiftShader 跑复杂光线追踪 shader 会直接冻结 GPU 进程。E2E 像素验证只能在有硬件加速的环境下做
- **"全黑"不一定是 WebGL 失败**：如果 shader 编译成功、链接成功、渲染循环在跑（FPS > 0），但画面全黑，问题可能在 shader 逻辑或几何体覆盖范围，而非 WebGL 初始化

## 相关知识

### NDC（Normalized Device Coordinates）

WebGL 的裁剪空间坐标范围是 [-1, 1]，经过透视除法后变成 NDC。PlaneGeometry(2,2) 的顶点恰好覆盖 [-1,1] 范围，所以 `gl_Position = vec4(position.xy, 0.0, 1.0)` 直接让四边形填满屏幕。

### Three.js 全屏四边形的正确做法

Three.js 社区的标准做法是用 `OrthographicCamera(-1, 1, 1, -1, 0, 1)` 配合 PlaneGeometry(2,2)，或者直接在顶点着色器里绕过矩阵。后者更简洁。
