# news-video 前端状态轮询竞态条件：误报"视频生成完成"

> **日期**: 2026-08-18  
> **分类**: 踩坑记录  
> **标签**: JavaScript, 前端, 竞态条件, 轮询, news-video  
> **来源**: hermes

---

## 背景/问题

news-video 前端点击"生成视频"按钮后，立即显示"✅ 完成! 视频已生成"，但后台 pipeline 刚刚开始运行（实际上在步骤 1/7 采集新闻）。

## 根因分析

前端 `startStatusPolling()` 在 `fetch('/api/generate')` 返回后立即开始轮询 `/api/status`：

```javascript
// 原始代码
function startStatusPolling(){
  if(statusTimer)clearInterval(statusTimer);
  statusTimer=setInterval(()=>{
    fetch('/api/status').then(r=>r.json()).then(s=>{
      if(!s.running){
        // 显示"✅ 完成! 视频已生成"
      }
    });
  },2000);
}
```

**竞态条件**：`/api/generate` 返回 `video_id` 后，pipeline 线程可能还没来得及写入 `running: true` 到状态文件。此时第一次 `/api/status` 查询读到的是**上一个任务的旧状态** `running: false`，前端误判为"完成"。

```
时间线：
T0: 用户点击生成按钮
T1: fetch('/api/generate') 发送 POST 请求
T2: 后端创建 video_id，返回 JSON
T3: 前端收到响应，调用 startStatusPolling()
T4: 前端查询 /api/status → 读到旧状态 running=false → 误报"完成"
T5: 后端 pipeline 线程终于启动，写入 running=true（太晚了）
```

## 解决方案

在 `startStatusPolling` 中加一个**启动等待阶段**：先每秒检查 `running` 是否变为 `true`，确认 pipeline 启动后再进入正常轮询：

```javascript
function startStatusPolling(){
  if(statusTimer)clearInterval(statusTimer);
  
  // 阶段1：等待 pipeline 真正启动（最多等 10 秒）
  let startupRetries=0;
  const startupCheck=setInterval(()=>{
    fetch('/api/status').then(r=>r.json()).then(s=>{
      if(s.running){
        clearInterval(startupCheck);
        addLog('running','Pipeline 已启动: '+(s.step||'初始化中'));
        
        // 阶段2：开始正常轮询（每 2 秒）
        statusTimer=setInterval(()=>{
          fetch('/api/status').then(r=>r.json()).then(s=>{
            if(s.step)document.getElementById('progressStep').textContent=s.step;
            if(s.progress)document.getElementById('progressBar').style.width=s.progress+'%';
            
            // 显示已运行时间
            if(s.started_at){
              const elapsed=Math.round((Date.now()-new Date(s.started_at).getTime())/1000);
              const min=Math.floor(elapsed/60);
              const sec=elapsed%60;
              const timeStr=min>0?min+'分'+sec+'秒':sec+'秒';
              const stepEl=document.getElementById('progressStep');
              if(stepEl)stepEl.textContent=(s.step||'')+' · '+timeStr;
            }
            
            if(!s.running){
              clearInterval(statusTimer);
              statusTimer=null;
              const btn=document.getElementById('genBtn');
              btn.disabled=false;
              btn.textContent='⚡ 生成视频';
              document.getElementById('cancelBtn').style.display='none';
              if(s.error){
                addLog('error','失败: '+s.error);
              }else{
                addLog('success','✅ 完成! 视频已生成');
                setTimeout(()=>{loadVideos();document.getElementById('progressPanel').classList.remove('active');},2000);
              }
            }
          }).catch(()=>{});
        },2000);
        return;
      }
      
      startupRetries++;
      if(startupRetries>10){
        // 10 秒后 pipeline 还没启动，可能失败了
        clearInterval(startupCheck);
        addLog('error','Pipeline 启动超时，请检查日志');
        const btn=document.getElementById('genBtn');
        btn.disabled=false;
        btn.textContent='⚡ 生成视频';
        document.getElementById('cancelBtn').style.display='none';
      }
    }).catch(()=>{});
  },1000);
}
```

## 修复后的流程

```
点击生成按钮
  ↓
API 返回 video_id
  ↓
阶段1：启动等待（每 1 秒查一次，最多 10 秒）
  ↓ 等到 running=true
显示"Pipeline 已启动: 1/7 采集新闻"
  ↓
阶段2：正常轮询（每 2 秒）
  ↓ running=false 且无 error
显示"✅ 完成! 视频已生成"
  ↓ 10 秒还没启动
显示"Pipeline 启动超时，请检查日志"
```

## 避坑提示

- **前端轮询后端状态时，初始状态可能是旧的**：异步 pipeline 线程启动有延迟，前端不能假设收到 `video_id` 就代表 pipeline 已经在运行
- **两阶段轮询模式**：先等启动确认（短间隔 1 秒），再进入正常轮询（长间隔 2 秒），避免误报
- **超时保护**：最多等 10 秒（10 次重试），超时后报错而非无限等待
- **时间显示**：利用 `started_at` 字段计算已运行时间，显示在步骤名旁边（如 `6/7 视频合成 · 3分15秒`），用户更直观
