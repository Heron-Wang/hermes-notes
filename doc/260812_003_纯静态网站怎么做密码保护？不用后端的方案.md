# 纯静态网站怎么做密码保护？不用后端的方案

> **日期**: 2026-08-12  
> **分类**: 经验总结  
> **标签**: 前端, 安全, HTML  
> **来源**: hermes

---

## 背景/问题

一个纯 HTML/CSS 静态网站（比如个人简历），没有后端服务器，但需要给联系方式加密码保护——让访客能看到基本信息，但电话、邮箱等隐私内容需要输入密码才能查看。

## 设计思路

### 方案选择

| 方案 | 优点 | 缺点 |
|------|------|------|
| 整站密码门 | 简单 | 不输入密码什么都看不到，影响展示 |
| **分段可见** ✅ | 基本信息公开展示，仅联系方式加密 | 实现稍复杂 |

选了**分段可见**：姓名、学历、工作经历、技术栈、项目展示都公开可见，只有联系方式区域需要密码解锁。

### 安全层次

纯前端密码保护**不是真正的安全措施**——源码对用户可见，理论上可以被绕过。它的目标是：

1. 防止搜索引擎爬虫抓取联系方式
2. 防止肉眼直接在源码里看到明文
3. 给访客一个需要授权的心理门槛

## 解决方案

### 1. HTML 结构：锁定/解锁两套 UI

```html
<!-- 锁定状态：显示密码输入框 -->
<div id="contactLocked">
  <p>🔒 联系方式已保护，请输入密码查看</p>
  <input type="password" id="pwInput" placeholder="输入密码">
  <button onclick="checkPw()">解锁</button>
</div>

<!-- 解锁状态：显示真实联系方式 -->
<div id="contactUnlocked" style="display:none">
  <p>📱 电话：***REDACTED***</p>
  <p>📧 邮箱：***REDACTED***</p>
  <button onclick="lockContact()">🔒 重新锁定</button>
</div>
```

### 2. 密码哈希存储（不明文出现在源码中）

用 djb2 哈希算法把密码转成数字，源码里只存数字不存明文：

```javascript
function djb2Hash(str) {
  let h = 5381;
  for (let i = 0; i < str.length; i++) {
    h = ((h << 5) + h) + str.charCodeAt(i);
    h = h & 0xffffffff;
  }
  return h >>> 0;  // ⚠️ 必须 >>>0 转无符号！
}
const PW_HASH = 3437355211; // 哈希值，不暴露明文

function checkPw() {
  const input = document.getElementById('pwInput').value;
  if (djb2Hash(input) === PW_HASH) {
    document.getElementById('contactLocked').style.display = 'none';
    document.getElementById('contactUnlocked').style.display = 'grid';
    sessionStorage.setItem('unlocked', '1');
  } else {
    alert('密码错误');
  }
}
```

### 3. sessionStorage 保持解锁状态

```javascript
// 页面加载时检查是否已解锁（同一标签页内有效）
window.addEventListener('load', () => {
  if (sessionStorage.getItem('unlocked') === '1') {
    document.getElementById('contactLocked').style.display = 'none';
    document.getElementById('contactUnlocked').style.display = 'grid';
  }
});

function lockContact() {
  sessionStorage.removeItem('unlocked');
  location.reload();
}
```

### 4. 清除源码中的明文密码

```bash
# 检查源码中是否还有明文密码
grep -c "你的密码明文" index.html
# 应该返回 0
```

注释里也不要写明文！把 `// djb2Hash('mypassword')` 改成 `// djb2 hash of password`。

## 避坑提示

- **djb2 哈希函数最后必须加 `>>>0`**，否则 JS 位运算返回有符号整数，哈希值会变成负数导致永远匹配不上（详见另一篇笔记）
- **注释里别写明文密码**——grep 能搜到，浏览器 F12 也能看到
- **sessionStorage vs localStorage**：sessionStorage 关闭标签页就失效，更安全；localStorage 会一直保持解锁
- **纯前端密码保护可被绕过**：懂技术的人看 JS 源码就能找到哈希值。如果要真正保护敏感数据，必须用后端验证
- djb2 是非加密哈希，碰撞率高。如果要更高安全性，考虑用 Web Crypto API 的 SHA-256
