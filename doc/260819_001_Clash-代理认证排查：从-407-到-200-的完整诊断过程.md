# Clash 代理认证排查：从 407 到 200 的完整诊断过程

> **日期**: 2026-08-19  
> **分类**: 运维排查  
> **标签**: Clash, 代理, 认证, 407, curl, 软路由  
> **来源**: hermes

---

## 背景/问题

软路由（192.168.0.104）上运行 Clash 作为全局代理。从 NAS 使用 curl 通过 Clash 代理访问外网时，遇到一系列认证错误：407 → 403 → 503 → 200。需要逐步排查找到正确的认证方式。

## 关键操作

### 1. 初步测试 — 无认证直接代理

```bash
curl -s -o /dev/null -w "HTTP状态: %{http_code}\n" \
  --proxy http://192.168.0.104:7890 https://www.google.com \
  --connect-timeout 5 --max-time 10
# 结果: HTTP状态 000, exit code 56 (CONNECT tunnel failed)
```

用 `curl -v` 查看详细错误：

```bash
curl -v --proxy http://192.168.0.104:7890 https://httpbin.org/ip \
  --connect-timeout 5 --max-time 10 2>&1 | tail -20
```

关键输出：
```
< HTTP/1.1 407 Proxy Authentication Required
< Proxy-Authenticate: Basic
* CONNECT tunnel failed, response 407
```

**407 = 代理需要认证**。Clash 的 mixed-port (7890) 开启了认证模式。

### 2. 尝试认证 — 用户名错误

```bash
# 用 heron 作为用户名
curl --proxy http://192.168.0.104:7890 --proxy-user heron:***REDACTED*** \
  https://httpbin.org/ip --connect-timeout 5 --max-time 10
# 结果: HTTP 403 Forbidden
```

**403 = 认证格式正确但用户名/密码不对**。用户名不是 heron。

### 3. 通过 Clash API 获取正确认证信息

Clash 提供 REST API（端口 9090），可以查询完整配置：

```bash
curl -s -H "Authorization: Bearer ***REDACTED***" \
  "http://192.168.0.104:9090/configs" | python3 -c "
import sys, json
data = json.load(sys.stdin)
print(f'mixed-port: {data.get(\"mixed-port\")}')
print(f'authentication: {data.get(\"authentication\")}')
print(f'allow-lan: {data.get(\"allow-lan\")}')
print(f'mode: {data.get(\"mode\")}')
"
```

输出：
```
mixed-port: 7890
authentication: ['nikki']
allow-lan: True
mode: rule
```

**认证用户名是 nikki**，不是 heron！

### 4. 正确认证 — 成功

```bash
curl -s --proxy http://192.168.0.104:7890 --proxy-user nikki:***REDACTED*** \
  https://www.google.com -o /dev/null -w "HTTP状态: %{http_code}\n"
# 结果: HTTP 200 ✅
```

### 5. 503 的误导

测试 httpbin.org 时返回 503，但 Google 和 GitHub 都正常。**503 是目标网站自身问题**，不是代理故障。排查时要用多个目标站点交叉验证。

## Clash API 常用接口

| 端点 | 方法 | 用途 |
|------|------|------|
| `/version` | GET | Clash 版本 |
| `/configs` | GET | 完整配置（端口、认证、模式） |
| `/proxies` | GET | 所有代理节点和分组 |
| `/proxies/{name}/delay` | GET | 测试单个节点延迟 |
| `/group/{name}/delay` | GET | 测试整组节点延迟 |
| `/rules` | GET | 路由规则列表 |
| `/connections` | GET | 当前活跃连接 |
| `/logs` | GET(WS) | 实时日志流 |

所有接口需要 `Authorization: Bearer {secret}` header。

### 查询代理分组状态

```bash
curl -s -H "Authorization: Bearer ***REDACTED***" \
  "http://192.168.0.104:9090/proxies" | python3 -c "
import sys, json
data = json.load(sys.stdin)
for name, info in data.get('proxies', {}).items():
    if info.get('type') in ['Selector', 'URLTest', 'Fallback']:
        print(f'[{info[\"type\"]}] {name} -> {info.get(\"now\")}  ({len(info.get(\"all\",[]))}个)')
"
```

### 测试整组节点延迟

```bash
curl -s -H "Authorization: Bearer ***REDACTED***" \
  "http://192.168.0.104:9090/group/自动选择/delay?timeout=5000&url=http://www.gstatic.com/generate_204" \
  | python3 -c "
import sys, json
data = json.load(sys.stdin)
ok = {k:v for k,v in data.items() if v > 0}
for k,v in sorted(ok.items(), key=lambda x:x[1]):
    print(f'  {k}: {v}ms')
"
```

## 结果/经验

| 错误码 | 含义 | 原因 |
|--------|------|------|
| 407 | Proxy Authentication Required | 代理需要认证，未提供凭据 |
| 403 | Forbidden | 认证格式对但用户名/密码错误 |
| 503 | Service Unavailable | 目标网站自身问题，非代理故障 |
| 000 | 连接失败 | 端口不通或网络中断 |

**排查要点**：
1. 遇到 407 先用 `curl -v` 确认认证类型（Basic/Digest）
2. 认证用户名不一定等于系统用户名，通过 Clash API `/configs` 查询 `authentication` 字段
3. 503 不代表代理有问题，换多个目标站点交叉验证
4. Clash API (9090) 是排查代理问题的利器，可以查配置、看节点延迟、查路由规则
