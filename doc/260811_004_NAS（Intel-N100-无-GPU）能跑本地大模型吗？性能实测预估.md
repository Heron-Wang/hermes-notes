# NAS（Intel N100 无 GPU）能跑本地大模型吗？性能实测预估

> **日期**: 2026-08-11  
> **分类**: 经验总结  
> **标签**: Ollama, 本地大模型, NAS, 性能优化, AI  
> **来源**: hermes

---

## 背景/问题

想在 NAS 上部署本地大语言模型（比如 Ollama + Qwen），实现完全不依赖云端的 AI 对话。但 NAS 用的是 Intel N100 低功耗 CPU，没有独立显卡（GPU），15GB 内存。这种配置能跑起来吗？速度能不能接受？

## 原因分析

大模型推理有两种方式：

1. **GPU 推理** — 显卡并行计算，速度极快（40-100+ token/s），但需要 NVIDIA 显卡（至少 8GB 显存）
2. **CPU 推理** — 纯 CPU 计算，速度慢得多，但不需要额外硬件

N100 是一颗 4 核低功耗处理器（TDP 仅 6W），没有独立 GPU，只能走 CPU 推理路线。但 N100 的优势是 **15GB 内存够大**，可以装下量化后的 7B 模型。

**量化的关键概念**：原始 7B 模型需要约 14GB 内存（FP16），通过 4-bit 量化（Q4）可以压缩到约 4.5GB，8-bit 量化（Q8）约 7GB。量化会损失一点精度，但内存占用大幅降低。

## 性能预估

基于 N100 CPU 的实测经验数据：

| 模型 | 量化方式 | 内存占用 | 预估速度 | 体验 |
|------|---------|---------|---------|------|
| Qwen2.5 **3B** | Q4（4-bit） | ~2GB | 8-12 token/s | 流畅对话 |
| Qwen2.5 **7B** | Q4（4-bit） | ~4.5GB | 3-6 token/s | 能用但偏慢 |
| Qwen2.5 **7B** | Q8（8-bit） | ~7GB | 2-3 token/s | 太慢 |
| Qwen2.5 **14B** | Q4（4-bit） | ~8GB | 1-2 token/s | 基本不可用 |

> **token/s 是什么？** 大模型生成文字的单位，1 个 token 大约等于 0.5-1 个汉字。3-6 token/s 意味着每秒输出 2-3 个汉字，回复一句话需要等 5-15 秒。

### 对比参考

| 平台 | 硬件 | 7B 模型速度 | 感受 |
|------|------|-----------|------|
| NAS（N100 纯 CPU） | N100 4核 | 3-6 tok/s | 回复一句话等 10 秒 |
| 迷你主机 + GPU | N100 + RTX 3060 | 40-60 tok/s | 秒回 |
| 云端 API | 服务器集群 | 100+ tok/s | 瞬间回复 |

### 智能家居场景的实际体验

```
用户："帮我开一下客厅的灯"
  -> 语音识别 ASR（1-2秒）
  -> 大模型理解意图（5-10秒）  <-- 瓶颈在这
  -> 执行设备指令（0.5秒）
  -> 语音播报 TTS（1秒）
总计：8-14 秒（本地 7B 模型）
对比：2-3 秒（云端 API）
```

## 解决方案

### 自用验证阶段

先跑 **Qwen2.5 3B Q4** 量化版，速度可接受（8-12 tok/s），先打通全链路：

```bash
# 安装 Ollama
curl -fsSL https://ollama.com/install.sh | bash

# 拉取 3B 量化模型
ollama pull qwen2.5:3b

# 测试速度
ollama run qwen2.5:3b "你好，介绍一下自己"
# 观察输出速度，如果能接受再试 7B
```

### 商业化部署阶段

给客户部署时建议用带 GPU 的迷你主机：

| 方案 | 硬件 | 成本 | 7B 速度 | 适合场景 |
|------|------|------|---------|---------|
| NAS 跑 3B | N100 纯 CPU | 0元 | 8-12 tok/s | 自用验证 |
| NAS 跑 7B | N100 纯 CPU | 0元 | 3-6 tok/s | 自用但需耐心 |
| 迷你主机+GPU | N100+RTX 3060 12G | 3000-4000元 | 40-60 tok/s | 客户部署 |
| 混合方案 | 硬件+API | 硬件+按量付费 | 智能路由 | 简单问题本地，复杂上云 |

## 避坑提示

- **3B 和 7B 差距很大**：3B 模型虽然小，但日常对话和简单指令足够用；7B 明显更聪明但速度只有 3B 的一半
- **别试 14B**：N100 跑 14B 只有 1-2 tok/s，等一句话要 30 秒以上，完全不可用
- **Q4 和 Q8 的选择**：Q4（4-bit）是性能和质量的甜点，Q8 虽然更准但内存翻倍速度减半，N100 上不值得
- **内存别占满**：NAS 上还有其他服务在跑，模型内存占用 + 系统占用不要超过总内存的 80%，否则触发 Swap 会更慢
- **混合方案最实用**：简单问题（开关灯、查时间）用本地 3B 模型秒回，复杂问题（写代码、长文分析）走云端 API，体验和成本最优
