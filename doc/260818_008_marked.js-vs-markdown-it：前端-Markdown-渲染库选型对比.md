# marked.js vs markdown-it：前端 Markdown 渲染库选型对比

> **日期**: 2026-08-18  
> **分类**: 技术知识  
> **标签**: JavaScript, Markdown, marked.js, markdown-it, 前端, CDN  
> **来源**: hermes

---

## 背景/问题

heron-web 项目前端原有一个手写的正则式 Markdown→HTML 渲染器（renderMarkdown 函数），覆盖基本语法但有以下痛点：
- 不支持嵌套列表（二级缩进子项）
- 不支持嵌套引用块
- `*斜体*` 可能误匹配列表项的 `*`
- 代码块语法高亮是简单正则，不是 tokenizer

需要决定是继续维护手写渲染器，还是引入成熟的 Markdown 解析库。两个主流选择：marked.js 和 markdown-it。

## 核心对比

| 维度 | marked.js | markdown-it |
|------|-----------|-------------|
| 体积 | ~28KB (min) | ~60KB (min) |
| 速度 | 更快（单遍正则替换） | 稍慢（parse→tokenize→render） |
| CommonMark 标准 | 部分符合 | 完全符合（通过 642 项测试） |
| 架构 | 单遍正则替换 | 两遍：parse→Token 数组→render |
| 插件系统 | 无（只能 hack renderer） | 完整插件 API（150+ 插件） |
| GFM (GitHub Flavored) | 需手动 `gfm: true` | 内置 table/task-list/strikethrough |
| 嵌套列表 | 有时出错 | 正确处理 |
| 表格扩展 | 基本支持 | 更完善（对齐、合并） |
| 目录(TOC) | 需第三方 marked-toc | 有 markdown-it-toc 插件 |
| 安全性 | 需手动 sanitize | 内置 `html: false` 可禁用原始 HTML |
| 语法高亮 | 需配 highlight.js | 内置 highlight 选项接口 |
| 维护活跃度 | 活跃 | 活跃 |

## 架构差异

**marked.js** — 单遍正则替换：
```
md 字符串 ──正则替换──→ HTML 字符串
```
极简，一个函数 `marked(md)` 返回 HTML。没有中间 AST，无法在渲染前修改 token。

**markdown-it** — 两遍解析：
```
md 字符串 ──parse──→ Token 数组 ──render──→ HTML 字符串
                    ↑ 可以在这里改
```
有完整的 token 中间层，插件可以在 parse 和 render 之间插入逻辑。支持任意嵌套。

## 推荐选择：markdown-it

理由：
1. 笔记有大量代码块+表格+嵌套列表，marked.js 的正则式在嵌套场景会出错
2. markdown-it 原生解决嵌套列表和表格对齐痛点
3. TOC 目录功能可通过 markdown-it-toc 插件直接生成（替代手写的 buildToc()）
4. `html: true` 直接放行内嵌 HTML（如 `<details>` 标签）
5. 体积差异（60KB vs 28KB）对通过 CF CDN 缓存的个人站可忽略

## 迁移方法

从手写 `renderMarkdown()` 换到 markdown-it，改动集中在 index.html 的 `<script>` 部分：

```html
<!-- CDN 引入（~60KB，CF 缓存后零延迟） -->
<script src="https://cdn.jsdelivr.net/npm/markdown-it@14/dist/markdown-it.min.js"></script>

<script>
// 初始化 markdown-it
const md = window.markdownit({
  html: true,        // 允许内嵌 HTML
  breaks: true,      // \n → <br>
  linkify: true,     // 自动识别 URL
  highlight: function(code, lang) {
    return highlightCode(code, lang);  // 复用现有高亮函数
  }
});

// 替换原来的 renderMarkdown 函数
function renderMarkdown(content) {
  return md.render(content);
}
</script>
```

CSS 适配：markdown-it 输出标准 HTML 标签（`<h1>`、`<table>`、`<pre><code>`），不是自定义 class。需要把原来的 `.md-h1` 等 CSS 选择器改为标准标签选择器，或用渲染规则插件加上自定义 class。

## 避坑提示

- **CDN 版本号要固定**：用 `markdown-it@14` 而非 `markdown-it@latest`，避免大版本升级导致 API 变化
- **`html: true` 有 XSS 风险**：如果笔记内容来自用户输入（留言板），需配合 sanitize-html 过滤。技术笔记场景（自己写的内容）可安全开启
- **`breaks: true` 对中文排版友好**：中文习惯每行换行，`breaks: true` 把 `\n` 转为 `<br>`，符合预期。但纯英文 Markdown 习惯空行分段，不需要 `breaks`
- **代码块高亮需 highlight.js 配合**：markdown-it 的 `highlight` 选项只是接口，实际高亮需要引入 highlight.js 或复用现有高亮函数
- **旧 CSS 类名需迁移**：手写渲染器输出 `<h1 class="md-h1">`，markdown-it 输出 `<h1>`。需要批量改 CSS 或用 `md.renderer.rules.heading_open` 插入 class

## 相关知识

### CommonMark vs GFM

| 标准 | 说明 | markdown-it 支持 |
|------|------|-----------------|
| CommonMark | Markdown 标准规范（642 项测试） | 默认开启 |
| GFM | GitHub 扩展（表格、任务列表、删除线、自动链接） | `linkify: true` + 内置 table/task-list |
| PHP Markdown Extra | 脚注、定义列表 | 需插件 |

### 手写渲染器的适用场景

手写正则式 Markdown 渲染器适合：
- 语法子集固定（只需要标题+列表+代码块+粗体）
- 零第三方依赖要求
- 文件体积敏感（嵌入式/离线页面）

一旦需要嵌套列表、表格对齐、TOC、脚注等高级功能，正则式的复杂度会指数增长，不如直接用 markdown-it。
